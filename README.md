# homelab-iac

Small IaC repo for a single-node Proxmox homelab focused on game servers.
README generated by AI.

## Architecture

```text
Proxmox
└── games-01 VM
    ├── Podman
    │   ├── playit.gg agent
    │   ├── Pterodactyl Panel
    │   ├── MariaDB
    │   └── Redis
    ├── Pterodactyl Wings
    └── Docker
        └── game-server containers
```

Responsibilities:

- **Proxmox** — physical host / virtualization
- **OpenTofu** — creates and updates VMs
- **Ansible** — configures guest OS and services
- **Podman** — general application containers
- **Pterodactyl** — manages game servers
- **Docker** — runtime used by Wings for game containers
- **playit.gg** — exposes game ports without router port-forwarding

## Local secrets

Do not commit credentials.

### Proxmox API token

Create a dedicated Proxmox API token and store it outside the repo:

```bash
mkdir -p ~/.config/homelab-iac
chmod 700 ~/.config/homelab-iac

cat > ~/.config/homelab-iac/secrets.env <<'EOF'
export PROXMOX_VE_API_TOKEN='opentofu@pve!provider=YOUR_TOKEN_SECRET'
export PROXMOX_VE_INSECURE=true
EOF

chmod 600 ~/.config/homelab-iac/secrets.env
source ~/.config/homelab-iac/secrets.env
```

The OpenTofu Proxmox user/role needs the permissions required by the resources in this repo, including VM configuration, datastore import, guest-agent read access, and power management.

### SSH key

Use a dedicated key for the provisioned VM:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/homelab_iac -C "homelab-iac"
ssh-add ~/.ssh/homelab_iac
```

Only the `.pub` key is referenced by OpenTofu.

### Ansible Vault

Application secrets live in:

```text
ansible/inventory/group_vars/games/vault.yml
```

Create/edit it with:

```bash
cd ansible
ansible-vault create inventory/group_vars/games/vault.yml
# later:
ansible-vault edit inventory/group_vars/games/vault.yml
```

Current secrets include:

```yaml
vault_playit_secret_key: "..."
vault_pterodactyl_db_password: "..."
vault_pterodactyl_db_root_password: "..."
vault_pterodactyl_app_key: "base64:..."
vault_pterodactyl_hashids_salt: "..."
vault_pterodactyl_wings_config: |
  ...
```

## Provisioning

Configure local OpenTofu values:

```bash
cp infra/tofu/terraform.tfvars.example infra/tofu/terraform.tfvars
$EDITOR infra/tofu/terraform.tfvars
```

Then:

```bash
source ~/.config/homelab-iac/secrets.env

make tofu-init
make tofu-plan
make tofu-apply
```

Generate the Ansible inventory:

```bash
make inventory
```

Configure the VM:

```bash
make ansible-games
```

Re-running both OpenTofu and Ansible should be safe and is the normal workflow after config changes.

## Game-server workflow

Infrastructure changes and game-server changes are intentionally separate.

### Create a new game server

1. Open the Pterodactyl Panel.
2. Create/select an allocation on `games-01`.
3. Create a server using the desired Nest/Egg.
4. Give it explicit RAM/disk limits.
5. Start it and verify it works over the LAN.
6. Create a matching playit.gg tunnel.

Example Minecraft allocation:

```text
192.168.1.50:25565
```

For playit.gg, use the **games VM LAN IP**, not `127.0.0.1`:

```text
Local address: 192.168.1.50
Local port:    25565
```

No router port-forward is required.

## Useful checks

```bash
# Podman-managed services
sudo podman ps

# Docker-managed game servers
sudo docker ps

# Wings
sudo systemctl status wings
sudo journalctl -u wings -n 100 --no-pager

# Playit
sudo systemctl status playit
sudo podman logs playit

# QEMU guest agent
systemctl status qemu-guest-agent
```

## Notes

- Keep the Pterodactyl Panel and Proxmox UI LAN/VPN-only.
- Back up `games-01` to separate Proxmox storage.
- The Redis bind mount must remain writable by the Redis container; the Podman Quadlet uses `:U` ownership handling.
- Wings uses Docker intentionally; Podman is used for the rest of the application stack.
